# 三思而后行 · 预检流程

用户让你做的东西，很可能已经有人做完了。这个技能的作用只有一个：**在动手之前，把"有没有现成的"这件事查实，并且留下证据。**

## 何时必须走这套流程

- 「帮我做一个 X」「设计一个 Y」「实现 Z」——任何要写代码/写长文的请求
- 「用 A 还是 B」——选型
- 「市面上有没有类似的东西」——直接问市场

不适用：继续、闲聊、纯事实问答（事实问答用普通检索即可）。

## 四步

### ① 盘点工具（不许假设）

先确认此刻真能用的检索通道，必要时跑一次自检。**某个通道坏了要明说**，并给出替代路径。
不要因为一个接口报错就断定"搜不了"，换一个再试。

### ② 按类型扫市场（至少三路）

详见 `docs/WORKFLOW.md` 的类型路由表。最低要求：

- **代码/仓库检索**：有没有人做过同样的东西（搜实现特征，不只搜产品名）
- **本生态市场**：有没有现成插件/技能
- **通用网页与社区**：口碑、坑、失败案例；官方口径要交叉验证

### ③ 摆证据

列成表：名称 · 热度 · 最近活跃 · 能力边界 · 与需求重合度 · 结论。
**没有这张表就不算做过调研。** 命中的东西要给出可点的链接。

### ④ 三问自我反驳

1. 我的方案比现成的强在哪？说不出就是重复。
2. 能不能直接用，或者去贡献（issue/PR）而不是另起炉灶？
3. 我漏了哪类来源？社区、反例、非英文资料、已经失败的项目。

## 判定漏斗

```
能直接用 ──→ 用，并说明为什么它够用
差一点   ──→ 提 issue / PR 贡献
确实空白 ──→ 自建，并写明「我查了哪些源、关键词是什么、没找到」
```

## 禁止

- 没查就宣布"没有现成方案"
- 把"我没找到"当成"不存在"
- 只引用官方文档就下结论
- 用一个引擎/一个站点代表整个互联网
